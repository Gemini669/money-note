# 小账本 MoneyNote V2.0

一个可以直接使用的中文个人记账网页。蓝白卡片界面，支持电脑和手机。无需登录、后端、数据库、API Key、构建或外部 CDN。

**账目仅保存在当前浏览器的 localStorage，不会提交到 GitHub，也不会发送到第三方服务器。请定期导出 JSON 备份。**

## 开始使用

- 直接打开根目录的 `index.html`，即可在支持本地文件存储的现代浏览器中使用。
- 更推荐通过 GitHub Pages 或本地静态 HTTP 服务访问，保证稳定的存储来源。若已有 Python，可在仓库根目录执行 `python3 -m http.server 8000 --bind 127.0.0.1`，然后用浏览器访问该服务。
- 所有样式、脚本和图标均在仓库内，资源路径均为相对路径，支持 GitHub Pages 项目子路径。页面无运行时 npm 依赖。
- 首次打开是空账本，不会自动加入示例交易。

### 日常记账

1. 点击“记一笔”（手机位于屏幕底部），选择收入或支出。
2. 输入大于 0、最多两位小数的人民币金额、日期、分类及可选备注。
3. 保存后立即更新收支、结余、分类分析和明细。刷新仍会保留。
4. 明细中的“编辑”可修改所有业务字段；“删除”必须再次确认，取消不会删除。

支出分类：餐饮、交通、购物、住房、医疗、教育、娱乐、其他。

收入分类：工资、奖金、投资、其他。

单笔金额上限为 **999,999,999.99 元**，最大 **10,000 条账目**，日期范围为 1900—9999 年。备注最多 200 个 UTF-16 字符（表情可能占两个字符）。金额按整数“分”计算，避免 `0.1 + 0.2` 的浮点计算误差。

### 月份、筛选和统计

- 顶部年月输入框和左右箭头选择月份，“回到本月”回到设备当前月份。日期按设备本地日历处理。
- 收入、支出、结余与分类图表始终统计**所选月份的全部账目**，不受下方搜索和分类筛选影响。
- 搜索支持备注、分类、日期及金额，忽略英文字母大小写；可与类别组合使用。“其他”会区分收入和支出。
- 明细按交易日期从近到远排列，同日按创建时间排序；每页 10 条，可翻页查看全部结果。
- 各类别支出占比同时提供颜色图表、文字金额和百分比；无支出时显示明确空态。百分比经四舍五入，合计可能存在 0.1% 的尾差。

## V2.0 年度报告

在电脑侧边栏点击「年度报告」；手机可通过顶部页面切换或底部「年度报告」入口进入。返回「账本概览」即可继续记账，原有收支明细和数据备份功能全部保留。

- **年份选择**：默认设备当前年份，可输入 1900—9999 年，使用上一年、下一年或「回到今年」。年度年份与月度记账筛选互相独立。
- **全年统计**：收入、支出、结余、收入笔数、支出笔数及月均收入和支出。范围为所选年份的 1 月 1 日至 12 月 31 日，依据交易日期 `date`，不依据 `createdAt`。
- **月均值**：全年合计除以固定 12 个月，包含没有记录的月份，最终四舍五入到整数分。例如全年 0.30 元支出，月均显示 0.03 元。
- **12 个月收支图**：绿色收入、蓝色支出；缺失月份为零。点选柱形、聚焦月份或按 Enter/空格可查看准确金额及笔数。
- **月度结余图**：收入减去支出，负结余绘制在零参考线下方并使用红点；图后列出最高和最低月份，包括所有并列月份。无记录月份的结余为零，也参与全年极值比较；全年无账目时显示空态。
- **年度分类**：支出分类排行及收入来源按金额从高到低排列，同时提供金额、笔数、占比和横向条形图。零金额分类在界面隐藏；全年无对应收支时显示空态。占比显示到一位小数，非零且小于 0.1% 时显示 `<0.1%`；各项四舍五入后合计可能有微小尾差。
- **精确数据与无障碍**：展开「查看 12 个月的精确金额与笔数」可查看全部月份和全年合计。SVG 图表具有标题、说明、键盘可操作的月份及可见的金额读数；图表和表格在窄屏容器内横向滑动，不挤压或截断金额。
- **自动更新**：新增、编辑（包括跨年份或修改类型）、删除、备份恢复及其他标签页同步后，年度统计与图表一起更新。

### 从 V1.0 升级的数据兼容

**V2.0 仅新增读取分析，没有数据迁移或自动重写。** 继续使用 `moneynote.data.v1`；备份 `format: "moneynote"`、`version: 1` 和 `transactions` 字段结构不变，V1 JSON 仍可导入和恢复。仅浏览年度报告、选择年份、点选图表和刷新不会改写账目。无需为了升级手动清理浏览器数据。

必须在原来的浏览器、原站点来源下访问升级后的页面，才能直接读取原账本。为防浏览器清理数据，升级前仍建议导出独立 JSON 备份。存储损坏或访问受限时年度报告显示不可用提示，不将无法读取的账目显示为真实零收支。

## 数据保存与备份

### 本地保存的边界

数据位于当前浏览器、当前来源（协议、域名和端口）的 `localStorage` 中，键名为 `moneynote.data.v1`。刷新或正常关闭浏览器不会主动清除数据。数据不会写入仓库文件。

- 换设备、换浏览器、换协议/域名/端口时不会自动同步；请用 JSON 迁移。
- 浏览器清理站点数据、隐私模式结束、重置配置或禁用存储，可能使账目不可用或丢失。
- `file://` 的存储行为由浏览器决定，不保证跨路径保留；不要把本地文件模式作为唯一备份。
- GitHub Pages 的多个项目可能共用同一个来源。此应用的本地存储不是加密保险箱；同来源脚本或有权限的浏览器扩展可能访问数据。
- 同一浏览器的不同标签页会同步变化。编辑中的账目被其他窗口修改时会阻止旧内容覆盖，并提示重新编辑。极端的跨窗口同时写入不提供数据库级事务保证。

### JSON 导出和恢复

1. 点击“导出 JSON”，下载**全部月份**的完整备份。
2. 妥善保存在你信任的位置；备份是明文，含备注等个人信息。不要将真实备份提交至 GitHub。
3. 点击“导入恢复”，选择本应用导出的 JSON 文件（最大 10 MB）。
4. 应用先完整检查结构、版本、每条记录、重复编号、日历日期、时间戳、收支分类和整数金额。不合法的文件不会部分导入，也不会覆盖现有账目。
5. 校验通过后显示笔数和总收支，必须确认才能**整体替换**。不是合并。空备份也会明确确认，取消则不变。

导入替换和删除都无法撤销，建议操作前先导出原有账目。恢复后自动切换到最近一笔账目所在月份。

备份结构版本为 1，字段严格校验，顶层字段为：

| 字段           | 说明                                        |
| -------------- | ------------------------------------------- |
| `format`       | 固定为 `moneynote`                          |
| `version`      | 固定为 `1`                                  |
| `exportedAt`   | UTC ISO 时间，如 `2026-10-19T01:00:00.000Z` |
| `transactions` | 账目数组，可为空                            |

每条账目必须且只能含有 `id`、`date`、`type`、`amountCents`、`category`、`note`、`createdAt`、`updatedAt`。`type` 为 `income` 或 `expense`，金额为正整数分。建议始终使用应用导出的文件恢复，不手动拼写备份。

### CSV 导出

“导出 CSV”导出全部月份，含日期、类型、分类、金额（元）、备注。UTF-8 BOM 便于 Excel 识别中文，支持逗号、双引号、换行。可能被电子表格识别为公式的备注会加前置单引号以中和公式。CSV 用于阅读分析，**不支持 CSV 导入**；恢复使用 JSON。

### 出错保护

- 存储空间不足或浏览器禁止写入时，显示错误，未成功保存的修改不会更新为已保存状态。
- 已有本地数据损坏时不会静默清空或自动覆盖：显示警告并暂停编辑；可“下载原始数据”留存，再导入有效备份恢复。
- 导入错误、取消确认、编辑校验失败均保留现有有效数据。
- 用户文本通过 `textContent` 等安全 DOM API 渲染，不将备注当作 HTML。页面 CSP 禁止网络连接，不引入分析、字体或第三方资源。

## 部署到 GitHub Pages

1. 将本版本分支通过 Pull Request 合并到 `main`。
2. 在 GitHub 仓库打开 **Settings → Pages**。
3. 在 **Build and deployment** 中选择 **Deploy from a branch**。
4. 选择 `main` 分支和 `/(root)`，保存。
5. 等待 GitHub Pages 部署完成后，使用 GitHub 显示的站点地址访问。

入口就是仓库根目录的 `index.html`，不需要打包、修改资源前缀或配置服务器。Pages 只发布静态代码，浏览器里的账目不会随部署上传。本站并非 PWA，不承诺关闭浏览器后离线重开；页面已加载后记账功能不需要网络。

## 开发和自动化检查

应用使用原生 HTML、CSS、JavaScript。`package.json` 仅用于开发测试，不是应用启动依赖。

需要 Node.js 20 或更新版本：

```sh
# 无第三方依赖的纯逻辑测试与语法检查
npm test
npm run check

# 可选：安装浏览器测试依赖（锁文件固定版本）
npm ci
npx playwright install chromium
npm run test:browser
```

Linux 若缺浏览器系统库，可用 `npx playwright install --with-deps chromium`（安装系统包需相应权限）。使用系统 Chromium 时：

```sh
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```

受限的容器若不支持 Chromium 沙箱，可仅在可信的测试环境追加 `CHROMIUM_NO_SANDBOX=1`。该选项只作用于测试浏览器，不影响应用。

测试使用独立临时浏览器上下文、内存测试数据和随机端口静态服务，运行在 `/money-note/` 项目子路径，**不会读取你的日常浏览器账目**。

- 纯逻辑：金额边界与精度、真实日期、严格导入、重复编号、大小上限、月度和年度汇总、跨年筛选、分类比例、12 个月补零、CSV 转义和公式中和。
- 浏览器：原有记账、筛选、备份、安全和存储异常回归，以及年度导航、图表数值、负结余、极值、年份边界、增删改/导入联动、只读兼容、多标签页同步和 320/390/768/1440 像素布局。
- `.github/workflows/check.yml` 在 push 和 PR 时运行语法、逻辑与 Chromium 浏览器测试。
